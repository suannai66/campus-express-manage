# 项目背景与当前基线

更新日期：2026-10-30。

## 项目与分工

四人开发校园快递代取管理系统，队长负责 F1/F2。同一学生可在不同订单中担任委托方或取件员。

| 分组 | 功能 | 代码目录标识 |
| --- | --- | --- |
| A（队长） | F1 注册登录、F2 实名认证 | identity |
| B | F3 发布需求、F4 浏览筛选 | orders |
| C | F5 接单履约、F6 评价信用 | fulfillment |
| D | F7 支付结算、F8 模拟钱包 | finance |

## 已确认设计

- 前端 Vue + JavaScript，后端 Python + FastAPI，数据访问采用 SQLAlchemy 2.0 + SQLite（由原 MySQL 选型在架构阶段三调整）。
- F1/F2 采用分层单体，局部隔离验证码来源及核心仓储接口。
- 注册与登录分离；手机号验证码登录，JWT 携带 sid，后端同时检查会话状态；退出只撤销当前会话。
- 认证包含未提交、待审核、已通过、已驳回；仅已通过对应 verified=true。
- 驳回可立即重提；待审核不可修改或重复提交，保留历史审核记录。
- 审核、记录与站内结果通知在同一数据库事务保存，任一失败回滚。
- 证件非公开保存，校验资料归属及管理员审核权限，展示学号脱敏。
- 认证通过是发单和接单的必要条件；信用等条件仍由相应业务模块负责。
- F1/F2 相关可靠性场景每类测试 20 次；尚未完成业务验收。
- 跨模块约定：F7 支付成功由 F3 订阅并转订单状态；F5 发布状态及完结事件，供 F4/F6/F7 使用；F7/F8 共用钱包余额变更能力。单体无需因此引入独立消息队列。
