## 2. 验收标准

点击上表的“查看完整验收标准”可跳转到对应功能。验收内容按功能单独展示，便于阅读长条目。

### F1 验收标准

**用户注册与登录**

| 验收标准 |
| --- |
| ① 时空拦截：未登录用户访问发布需求、接单大厅等需登录页面时强制跳转登录页，登录后自动回跳原页面； |
| ② 同一手机号重复注册提示“该手机号已注册”，验证码 60 秒内不可重复发送； |
| ③ 退出登录后 Token 立即失效，订单等个人页面不可再访问； |
| ④ 可靠性：重复注册、请求超时重试场景各测试 20 次，重复账号及失败却返回成功的次数均为 0 |

### F2 验收标准

**学生身份实名认证**

| 验收标准 |
| --- |
| ① 时空拦截：未认证用户不能发布需求、不能接单，点击时引导去认证； |
| ② 审核结果（通过/驳回）24 小时内站内通知到达，驳回必须填写理由； |
| ③ 姓名学号与证件信息一致方可审核通过，证件号中间位脱敏展示； |
| ④ 可靠性：认证重复提交（含超时重试）、上传失败、审核保存失败场景各测试 20 次，额外待审核申请、非法状态转换及失败却返回成功的次数均为 0 |

### F3 验收标准

**发布代取需求**

| 验收标准 |
| --- |
| ① 快递公司、取件码、取件点、送达地址等必填项为空时阻断提交并逐项提示； |
| ② 时空拦截：未实名认证用户提交发布时引导去 F2 认证； |
| ③ 提交成功生成待支付订单，订阅到 F7 支付成功事件后自行流转为“待接单”并进入 F4 大厅 |

### F4 验收标准

**代取任务浏览与筛选**

| 验收标准 |
| --- |
| ① 列表仅展示已支付且“待接单”的需求，本人发布的需求不出现在自己的接单候选列表； |
| ② 多条件组合筛选结果正确，无匹配时展示空态提示； |
| ③ 需求被接单或取消后，订阅 F5 状态事件 30 秒内同步刷新列表 |

### F5 验收标准

**接单与履约管理**

| 验收标准 |
| --- |
| ① 权限校验：仅实名认证通过且为本单取件员可推进订单状态，他人操作返回 403； |
| ② 取件码核对错误不能确认取件，连续错误 3 次锁定订单并通知双方； |
| ③ 每次状态变更发布事件，F4 大厅与用户订单页订阅刷新； |
| 订单完结触发 F6 评价入口与 F7 结算（事件） |

### F6 验收标准

**评价与信用体系**

| 验收标准 |
| --- |
| ① 时空拦截：仅状态为“已送达”的订单显示评价入口，评价提交后不可修改； |
| ② 信用分按近 30 单均分实时重算，信用等级徽标同步更新； |
| ③ 信用分低于 3.0 的取件员在 F5 接单时被拦截并提示（同模块联动） |

### F7 验收标准

**订单支付与费用结算**

| 验收标准 |
| --- |
| ① 金额=基础运费+小费，与页面明细一致（精确到分），重复支付请求只扣款一次（幂等）； |
| ② 时空拦截：未支付订单不进入 F4 大厅、不可被接单； |
| ③ 支付成功仅发布事件（不回写），订单状态由 F3 自行流转； |
| 订阅 F5 完结事件后取件员收益 T+0 入账 |

### F8 验收标准

**钱包充值与提现**

| 验收标准 |
| --- |
| ① 金额必须为正数、提现不得超过余额，非法输入阻断并提示； |
| ② 同一笔充值回调重复到达只入账一次（流水表唯一约束幂等）； |
| ③ 改余额与插流水在同一事务、任一失败整体回滚； |
| 提现状态由“处理中”延迟自动流转“已到账” |

## 3. 集成关系清单

全组共 10 条集成关系（依赖/提供/联动/共用），全部非“无”，满足“至少 2 条”要求。跨模块写操作一律走事件订阅（第 5/6/7 条），无双向调用环；第 8/9/10 条为同模块内部协作，体现高内聚。

| 序号 | 主功能 | 关系类型 | 关联功能 | 集成说明 | 接口契约 / 事件 |
| --- | --- | --- | --- | --- | --- |
| 1 | F1 用户注册与登录 | 提供 | F2、F3、F5、F6、F7、F8 | 登录上下文：当前用户 UID 与手机号，作为各功能识别用户身份的唯一依据 | GET /api/auth/current → {uid, phone} |
| 2 | F2 学生身份实名认证 | 提供 | F3、F5 | 认证状态 verified：未认证用户禁止发布需求、禁止接单 | GET /api/auth/verify-status → {verified, rejectReason} |
| 3 | F3 发布代取需求 | 提供 | F4、F5 | 订单数据：orderId、取件码、取件点、送达地址、金额 | POST /api/orders → {orderId, amount}；<br>GET /api/orders/{orderId} |
| 4 | F3 发布代取需求 | 依赖 | F7 | 提交发布后调起支付接口，按订单金额完成付款 | POST /api/pay/prepay |
| 5 | F7 订单支付与费用结算 | 联动 | F3 | 支付成功后仅发布事件，由 F3 订阅并自行流转订单状态为“待接单”（事件订阅，不直接回写） | 支付成功事件 |
| 6 | F5 接单与履约管理 | 联动 | F4 | 每次状态流转发布事件，需求大厅订阅后 30 秒内同步刷新 | 订单状态事件 |
| 7 | F5 接单与履约管理 | 联动 | F6、F7 | 订单完结发布事件：F6 开放评价入口、F7 结算收益入账 | 订单完结事件 |
| 8 | F6 评价与信用体系 | 提供 | F5 | 取件员信用分：低于 3.0 分时限制接单（C 模块内部协作） | GET /api/users/{uid}/credit → {score, level} |
| 9 | F8 钱包充值与提现 | 提供 | F7 | 余额扣款/入账能力，供支付与结算调用（D 模块内部协作） | WalletService.changeBalance() |
| 10 | F7 订单支付与费用结算 | 共用 | F8 | 支付/结算与充值提现共用同一钱包核心方法与两张表（D 模块内部） | wallet、wallet_transaction 表 |
