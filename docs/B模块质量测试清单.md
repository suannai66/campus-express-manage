# B模块质量测试清单

成员 B 负责 F3 发布需求与 F4 浏览筛选。本清单记录新增质量回归用例、预期结果和统计口径，可作为个人工作清单的测试依据。测试使用临时数据库和虚构资料，不修改开发数据库。

## 用例统计

- 新增质量用例共 **31 个**：后端 23 个、浏览器 8 个。
- 后端按 `unittest` 的测试方法计数；一个方法内的多组边界输入、20 次事件重放均不额外计数。
- 浏览器按 Playwright 展开的用例计数，320、768、1440 像素分别计 1 个用例。
- B 模块相关用例现共 **84 个**：原后端 37 个、新增后端 23 个、原 F3/F4 浏览器 15 个、新增浏览器 8 个、已有真实发布支付接单联调 1 个。
- 公共冒烟测试 3 个不计入个人模块用例。新增的 31 个均有明确质量目标，原有用例尚未逐条划分质量属性，因此“质量需求对应的测试用例数”可保守填写 **31 个**。
- 当前版本没有正式大规模并发或响应时间指标。本清单的千条订单检查验证查询次数和数据库分页，不等于吞吐量、延迟或生产环境容量验收。

## 后端质量用例

文件：`backend/tests/test_orders_quality.py`。测试名称中的 `q01` 等编号与下表对应。

| 编号 | 质量目标 | 操作或故障 | 预期结果 |
| --- | --- | --- | --- |
| Q01 | 身份安全 | 未登录查询列表、详情、报价、创建和预占 | 均返回 401，订单和幂等记录不变 |
| Q02 | 越权及隐私 | 其他用户读取详情或发起支付预占 | 与不存在订单返回相同 404，不泄露取件码、地址，不改变数据 |
| Q03 | 数据隔离 | 两个用户分别查询 mine 的 all、publisher、courier 范围 | 只返回本人相关订单，不混入其他用户订单 |
| Q04 | 服务端权限 | 伪造发布者、取件员、版本、付款状态、费用、佣金等字段 | 422，订单与幂等表无写入 |
| Q05 | 输入边界 | 公司、取件码、地址和备注分别提交长度上限及上限加一 | 上限合法，上限加一拒绝；拒绝请求不创建订单 |
| Q06 | 请求契约 | 缺失幂等键、键长 7/8/100/101 | 拒绝缺失和越界键，接受长度 8 与 100 |
| Q07 | 时间边界 | 固定时钟，提交当前时刻、未来 1 微秒、7 天整、7 天加 1 微秒 | 仅接受未来 1 微秒和 7 天整 |
| Q08 | 严格类型 | 版本传布尔、字符串、小数、零、负数、null | 422，版本和支付预占不改变 |
| Q09 | 依赖结果校验 | 报价金额不守恒、小费不匹配、类型错误、过期、无时区、佣金越界 | 503，不生成订单和幂等结果 |
| Q10 | 故障恢复及错误脱敏 | 报价依赖抛数据库异常后恢复，使用原键重试 | 先 503、不泄露内部异常，恢复后只创建一单 |
| Q11 | 创建事务原子性 | 订单 flush 后、幂等结果保存前发生数据库故障 | 订单和幂等结果一起回滚，原键重试及再次重放成功 |
| Q12 | 预占事务原子性 | 预占状态变更后、幂等结果保存前故障 | 订单恢复原状态，原键可重试且只增加一次版本 |
| Q13 | 响应丢失恢复 | 创建已提交，再以原键提交相同请求 | 返回原 201 和原订单，不再次报价、不重复写入 |
| Q14 | 并发幂等 | 屏障同时发起两个相同键创建请求 | 只保存一单；竞争可返回 409/503，原键重试收敛到同一结果 |
| Q15 | 并发状态一致性 | 两个请求以同一版本同时预占 | 只有一个成功，版本只增加一次，后续查询恢复同一预占 |
| Q16 | 事件边界与回滚 | 事件聚合、时间、版本、金额类型、失败代码或额外字段非法 | 拒绝事件，不留下支付事实、回执或部分订单变更，合法事件仍可处理 |
| Q17 | 消费事务原子性 | 支付处理已改变状态后注入回执保存故障 | 状态、支付事实、回执全部回滚；原事件重试成功 |
| Q18 | 事件防篡改 | 已处理事件保留原 ID 但修改金额 | 409 幂等冲突，已提交订单、支付事实和回执不变 |
| Q19 | 重复投递可靠性 | 同一支付成功事件连续重放 20 次 | 订单不再变更版本，支付事实和回执各保留一条 |
| Q20 | 分页稳定性 | 23 条相同创建时间订单分三页读取，再读第二页 | 排序确定，跨页不重不漏，total 一致 |
| Q21 | 非法筛选防护 | 地点或 scope 注入字符串，分页和金额传指数、全角数字、小数等 | 422，随后正常创建仍可成功 |
| Q22 | 时区一致性 | 用 UTC+8 表示同一送达时刻作为筛选上下限 | 能准确包含对应订单 |
| Q29 | 查询资源开销 | 1000 条订单，读取第一页及第十页，每页 100 条 | 每次返回 100 条、total=1000，只执行 2 次订单 SELECT，使用数据库 LIMIT/OFFSET |

## 执行方式

在仓库根目录执行后端质量测试：

```powershell
$env:PYTHONPATH = 'backend'
.venv\Scripts\python.exe -m unittest discover -s backend/tests -p test_orders_quality.py -v
```

在 frontend 目录执行浏览器质量测试：

```powershell
$env:PW_BROWSER_CHANNEL = 'msedge'
npm run test:orders -- orders-quality.spec.js
```

完整 F3/F4 及公共冒烟回归使用 `npm run test:orders`。真实发布支付接单联调使用 `npm run test:fulfillment -- -g 'B 真实发布页面'`。使用已安装的 Chromium 时可取消 `PW_BROWSER_CHANNEL`。
